# Definition of Ready / Definition of Done
Версия 1.1 (ЛР 4), предложение для командного согласования.

## DoR
- Есть Issue, цель, один ответственный, эпик/WBS, MoSCoW и оценка.
- Критерии приёмки однозначны; источник требования указан.
- Входные данные доступны, лицензия и QA известны; блокеры названы.
- Задача <=6 ч; большая история разбита, зависит только от явных входов.

## DoD документа
- Нет пустых разделов; факты имеют источники, допущения подписаны.
- Значения, сроки и бюджеты совпадают с data/processed/plan.json.
- PR связан с Issue, имеет метку; другой участник сделал ревью.
- Заказчик подтвердил критерии, если задача требует приёмки.

## DoD данных и расчётов
- Входы имеют provenance, checksum, дату, CRS, лицензию и описание обновления.
- Нулевые DN/облака/снег/вода/насыщение исключены; пропуски не превращены в ноль.
- Геометрии валидны, ID уникальны, слои в согласованных границах.
- Есть тест известного ответа, граничных значений и NoData.
- Ноутбуки выполняются последовательно и сохранены без outputs/execution_count.
- Карты содержат легенду, дату, единицы, атрибуцию и ограничения.
- Ruff, pytest, validate_data и проверка ноутбуков прошли; обязательный quality зелёный.
- В main только squash PR с одним человеческим одобрением, без обхода защиты.

## DoD спринта
Есть обзор, ретроспектива, реальные план/факт часов, статус-отчёт, обновлённые риски и релиз. Подготовленные шаблоны не считаются проведёнными встречами.
